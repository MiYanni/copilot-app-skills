# copilot-app-skills
Reusable skills for the GitHub Copilot app.

## Personal skills

[copilot-attribution](.copilot/skills/copilot-attribution/SKILL.md) omits attribution from command messages so bot and CI comment triggers still work. Commit messages use the inline prefix ` 🤖Copilot🤖:  ` (one leading space and two spaces after the colon), followed by the subject on the same line so GitHub displays both together. Other external interactions on your behalf, including PR descriptions, non-command comments, and review replies, start with the exact unformatted line `🤖Copilot🤖`, with the message body starting on the next line.

The skill source is in `.copilot\skills\copilot-attribution\SKILL.md`. To use it as a personal skill, copy the `copilot-attribution` directory into your user-level `.copilot\skills` directory (on Windows, `%USERPROFILE%\.copilot\skills`). Adding it to this repository does not install or enable it globally.

[azdo-pr-build-rerun](.copilot/skills/azdo-pr-build-rerun/SKILL.md) prefers Azure CLI (`az rest`) to retry failed jobs within an existing Azure Pipelines PR build, preserving its source, inputs, and PR context. It requires Azure DevOps access through Microsoft Entra authentication; an already configured Azure DevOps PAT/CLI extension is a separate alternative. GitHub CLI (`gh`) discovers and verifies PR checks, but GitHub check re-requests are not a reliable user-token trigger for Azure Pipelines. The skill includes Windows-safe commands, source-revision checks, stale merge-ref blockers, duplicate-run prevention, and job-attempt/PR-check verification. It distinguishes unchanged-source retries from fresh validation: retrying an old build cannot test newer source or inputs, and manually queueing a PR merge ref does not guarantee PR validation semantics. Command-comment fallbacks require explicit authorization. The original directory/name is retained for in-place upgrades; install or update it by copying the `azdo-pr-build-rerun` directory into your user-level `.copilot\skills` directory.

[draft-pr-creation](.copilot/skills/draft-pr-creation/SKILL.md) creates every new pull request in the Draft state, whether through the app's PR tool, `gh pr create --draft`, or the API. Drafts let you review and iterate with Copilot first; you decide when to mark the PR ready, which signals your team to review it for approval. Copilot never marks a PR ready unless you explicitly ask, and reports rather than falls back when a draft cannot be created. Install it by copying the `draft-pr-creation` directory into your user-level `.copilot\skills` directory.
