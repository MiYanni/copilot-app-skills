# copilot-app-skills
Reusable skills for the GitHub Copilot app.

## Personal skills

[copilot-attribution](.copilot/skills/copilot-attribution/SKILL.md) omits attribution from titles and command messages so titles stay clean and bot and CI comment triggers still work. Commit messages on every host, including GitHub and Azure DevOps (AzDO), use the inline prefix ` 🤖Copilot🤖:  ` (one leading space and two spaces after the colon), followed by the subject on the same line. This includes Azure DevOps Git commit API `comment` fields, which are commit messages rather than discussion comments. Other external interactions on your behalf, including PR descriptions, non-command comments, and review replies, start with the exact unformatted line `🤖Copilot🤖`, with the message body starting on the next line.

The skill source is in `.copilot\skills\copilot-attribution\SKILL.md`. To use it as a personal skill, copy the `copilot-attribution` directory into your user-level `.copilot\skills` directory (on Windows, `%USERPROFILE%\.copilot\skills`). Adding it to this repository does not install or enable it globally.

[azdo-pr-build-rerun](.copilot/skills/azdo-pr-build-rerun/SKILL.md) prefers Azure CLI (`az rest`) to retry failed jobs within an existing Azure Pipelines PR build, preserving its source, inputs, and PR context. It requires Azure DevOps access through Microsoft Entra authentication; an already configured Azure DevOps PAT/CLI extension is a separate alternative. GitHub CLI (`gh`) discovers and verifies PR checks. It never calls GitHub check re-request endpoints, which accept only GitHub App tokens and return 404 for `gh` OAuth or PAT tokens. The skill includes Windows-safe commands, source-revision checks, stale merge-ref blockers, duplicate-run prevention, and job-attempt/PR-check verification. It distinguishes unchanged-source retries from fresh validation: retrying an old build cannot test newer source or inputs, and manually queueing a PR merge ref does not guarantee PR validation semantics. Command-comment fallbacks require explicit authorization. The original directory/name is retained for in-place upgrades; install or update it by copying the `azdo-pr-build-rerun` directory into your user-level `.copilot\skills` directory.

[draft-pr-creation](.copilot/skills/draft-pr-creation/SKILL.md) creates every new pull request in the Draft state, whether through the app's PR tool, `gh pr create --draft`, or the API. Drafts let you review and iterate with Copilot first; you decide when to mark the PR ready, which signals your team to review it for approval. Copilot never marks a PR ready unless you explicitly ask, and reports rather than falls back when a draft cannot be created. Install it by copying the `draft-pr-creation` directory into your user-level `.copilot\skills` directory.

[no-direct-quotes](.copilot/skills/no-direct-quotes/SKILL.md) prevents text written by people (you, coworkers, teammates, managers, customers, and others) from being reproduced verbatim in AI-generated PR descriptions, issues, commits, comments, review replies, chat responses, and files. Copilot paraphrases instead, avoids attributing words to named individuals by default, and links to shared sources rather than copying them, protecting the integrity of the original authors. Code, commands, error messages, and other technical text are not affected, and you can explicitly request a specific quote for a specific output. Install it by copying the `no-direct-quotes` directory into your user-level `.copilot\skills` directory.
